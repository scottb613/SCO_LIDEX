SCO LIDEX Instructions
======================

1. Back up your route
---------------------
Before running SCO LIDEX, make a full backup of the route folder. This is
especially important before using Overwrite or Clean Tile Wipe.

2. Start SCO LIDEX
------------------
Run SCOLIDEX.exe. The GUI should open without a console window.
If SCO LIDEX is already running, a second launch will show a notice instead of
opening another copy.

Optional desktop shortcut:
  1. Place the SCOLIDEX folder where you want to keep it.
  2. Run AddShortcutDesktop.cmd from the top-level SCOLIDEX folder.
  3. A desktop shortcut will be created for SCO LIDEX.

The shortcut points to the application here:
SCOLIDEX-win-x64\SCOLIDEX.exe

3. Route Path
-------------
Use Browse to select an Open Rails route folder, or type/paste its full path into
Route Path. Use Recent to open a menu of the five most recent valid routes.
The list is stored in
%LocalAppData%\SCOLIDEX\route-history.json; folders that no longer exist or no
longer contain a .trk file are removed automatically.

Example:
M:\OpenRails\Train Simulator\routes\MyRoute

4. Mode
-------
Append:
  Processes only tiles with no usable elevation data.

Overwrite:
  Rebuilds elevation for selected tiles even if they already contain elevation.
  Existing texture, water, and overlay selections should be retained unless
  Clean Tile Wipe is enabled.

5. Options
----------
Create Route Tiles:
  Builds or updates normal 8m terrain tiles.

Create DM Tiles:
  Builds or updates TSRE-style lo_tiles.
  Existing DEMEX-style distant mountain tiles are incompatible with the TSRE
  style used by SCO LIDEX. If detected during Run, they are purged and rebuilt
  as TSRE-style lo_tiles.

Create Map Tiles:
  Creates one 4096x4096 OpenStreetMap texture for each selected normal terrain
  tile. Map tiles do not apply to Distant Mountain terrain.

  Scan selects the smallest Geofabrik regional extract that covers the route,
  reports its current download size/date, verifies the bundled OSM/PBF driver,
  and checks map/terrain coordinate round trips and output names. Scan does not
  download the regional PBF or modify the route.

  Run asks for confirmation before downloading. The anonymous Geofabrik PBF is
  resumable and stored with the route:

  <Route>\osm_data\geofabrik\<region-id>.osm.pbf

  SCO LIDEX also writes <Route>\osm_data\osm-cache.json. The manifest
  identifies the provider, region, URL, source date, expected size, geographic
  bounds, relative PBF path, and creating version so LIDEX or future route tools
  can validate and reuse the extract.

  A matching legacy PBF under LocalAppData\SCOLIDEX\map-data is copied and
  verified into the route, then the legacy copy is removed. Interrupted
  downloads use a .part file beside the final route-local PBF. If the route
  cache cannot be written, LIDEX retains AppData as a compatibility fallback.

  The small shared Geofabrik index remains under
  %LocalAppData%\SCOLIDEX\map-data. A
  %LocalAppData%\SCOLIDEX\cache-registry-v1.json registry records known route
  cache locations. The route manifest remains authoritative if the registry is
  lost or rebuilt.

  On exit, SCO LIDEX lists every known purgeable OSM data cache separately:
  regional PBFs and incomplete downloads. Every purge checkbox is clear by
  default. The small shared Geofabrik index is internal application data and is
  never offered for deletion. Select only the OSM caches to remove, then choose
  Purge Selected; Keep All leaves every cache untouched, and Cancel Exit
  returns to the application.

  Purge Selected remains available when nothing is checked. In that case it
  plays the failure buzz, deletes nothing, and keeps the exit dialog open.

  Generated terrain_maps PNG files are route output, not purgeable OSM cache.
  SCO LIDEX never offers those images for deletion and never removes the
  terrain_maps folder during cache cleanup.
  SCO LIDEX does not use the bulk-restricted public OpenStreetMap editing API.

  Each map is written to TSRE's F3 terrain_maps\<tile-hash>.png cache using the
  same X*10000+Y filename convention used by TSRE (TSRE map Y is the negative
  of the terrain Z shown by LIDEX). A matching existing PNG is overwritten
  directly. SCO LIDEX does not create a map ACE and does not change
  terrain .t materials or patch UV assignments.

  TSRE's existing Show/Hide Map command can load this PNG as the separate F3
  overlay and reveal the unchanged terrain when hidden. SCO LIDEX cannot clear
  or change an overlay already loaded by a running TSRE process; reopen or
  reload the route when testing replaced cache images.

  Map output uses compressed 4096x4096 PNG files in the route terrain_maps cache.
  Processing loads selected-route geometry once and retains it while two 4096
  bitmaps are rendered concurrently. Large routes still require substantial
  time, memory, and disk space.

  Every OSM vertex is projected into the exact tile-local meter frame used by
  terrain sampling, including the standard 16m east/16m south correction or a
  route's TsreGeoProjection. No API key, external route editor, or MSTS runtime
  is required; bundled GDAL reads PBF and SCO LIDEX writes the TSRE F3 PNG
  cache using TSRE's naming and projection behavior.

  The reference map texture uses TSRE's OSM drawing style rather than a web
  map-tile theme: warm off-white background, pale land-use polygons, outlined
  buildings, railway styling, and two-pass cased roads. Primary highways use
  TSRE's red center, secondary highways orange, tertiary highways yellow, and
  motorway/trunk roads orange-red. The thin bright-red marker line shown by
  TSRE is an editor/KML overlay and is not part of the map texture.

Clean Tile Wipe (Destructive):
  Rebuilds terrain .t files from a clean template. This can repair corrupted
  terrain tiles but may wipe texture, water, overlay, or other tile-specific
  edits. Leave this off unless you are repairing damaged tiles. SCO LIDEX ships
  clean terrain templates in the application folder. Scan checks that the clean
  template is available before Run is enabled.

Scan source handling:
  Scan tests and reports USGS 1m, 5m~, and 10m, Copernicus 30m global, and the
  Geofabrik map source separately. The final SCAN SOURCE STATUS block preserves
  FAILED indications and prints the exact Run plan. The Details line clearly
  distinguishes SERVICE UNAVAILABLE from SERVICE ONLINE / NO ROUTE COVERAGE in
  both Scan and the following Run.

  Scan can pass with warnings when another source can complete useful selected
  work. For example, accessible Copernicus coverage enables global normal and
  Distant Mountain terrain when USGS is unavailable. Failed USGS services and
  sources with no representative coverage are disabled for that Run and are not
  polled again tile by tile.

  Geofabrik failure does not block normal terrain or Distant Mountains. Maps can
  still run from a usable cached regional index and PBF extract. If no valid map
  cache exists, only the map stage is skipped and its failure remains visible in
  the Scan summary. Run is disabled only when no selected production stage has a
  viable source path or a route/file validation error is blocking.

Scan Override:
  Disables the Scan button and allows Run immediately. Use this only when you
  intentionally want to bypass the preflight checks.

Help:
  Opens this instruction file inside SCO LIDEX as a formatted, read-only
  document. Text can be selected and copied, but the instructions cannot be
  accidentally edited from the Help window.

6. Terrain Output
-----------------
Normal - 8m:
  Creates the standard Open Rails normal-terrain format using a 256x256 height
  grid with 8m post spacing. This is the supported output for normal route use.

Experimental - 4m:
  Deactivated in this build. The control remains visible but disabled, and Scan
  and Run always use Normal - 8m output.

  The isolated test mechanism remains in source: 512x512 _y.raw writing, 4m
  metadata, complete KML-footprint generation, shared edge/corner merging, no
  DM, all-or-nothing terrain preparation, and optional maps. It can be restored
  later with the single internal experimental feature switch after joint Open
  Rails format testing resumes.

7. Selection
------------
Use Route Tiles:
  Uses existing route terrain tiles.

Use Text File:
  Uses ROUTE\SCOLIDEXTiles.txt. This processes exactly the listed tiles and does
  not use Tile Radius.

  Format:
  -04bea740
  -04bea744
  -04bea748

Use Marker File:
  Uses ROUTE\[RouteName].mkr. Tile Radius expands around each marker tile.

Use KML File:
  Uses ROUTE\[RouteName].kml. Tile Radius expands around KML-derived tiles.

Use Track Database:
  Uses ROUTE\[RouteName].tdb. Tile Radius expands around tiles referenced by
  the track database.

8. Radius
---------
Tile Radius:
  Applies to Marker, KML, and Track Database selections.
  Radius 0 means only the source tile.
  Radius 1 means a 3x3 block around each source tile.
  Radius 2 means a 5x5 block around each source tile.

DM Radius:
  Controls distant mountain coverage around the selected source.
  Distant mountain tiles use 10m / 1/3 arc-second data where available and
  fall back to 30m (global) Copernicus data outside US coverage.

Global elevation fallback:
  SCO LIDEX tries USGS 1m, 5m~, and 10m sources first. Posts still lacking
  coverage are read anonymously from Copernicus DEM GLO-30 Public on AWS Open
  Data and are counted as 30m (global). This is low-resolution source data even
  though it is resampled onto the normal ORTS 8m post grid.

  Copernicus GLO-30 is a Digital Surface Model (DSM), so elevations may include
  vegetation, buildings, and infrastructure. Missing public tiles are treated
  as unavailable data, never silently as zero elevation. Ocean-only areas do
  not publish COG tiles.

9. Normal terrain sampling
--------------------------
Open Rails normal terrain tiles use a 256x256 _y.raw height grid. Those are
height posts spaced 8m apart. Because there are 255 spaces between 256 posts,
the stored height-post span is 2040m inside a nominal 2048m tile.

SCO LIDEX samples normal route terrain using that true 8m post spacing. This
avoids stretching the 256 raw posts across the full tile footprint and should
improve alignment with route/map overlays.

Distant Mountain tiles are much lower resolution and still use their existing
lo_tile sampling behavior.

10. Advanced Geo Bias
---------------------
The N/S and E/W bias sliders shift terrain features in meters without moving
the route tiles themselves. Positive values move terrain toward N or E, shown
on the left side of each slider. Leave both at 0 unless you are calibrating a
route.

For standard-projection routes, v1.100 includes a built-in 16m east and 16m
south compatibility correction for TSRE map alignment. A slider value of 0
uses this corrected baseline. Any Advanced Geo Bias value is an additional
route-specific adjustment.

During Run, these values shift where SCO LIDEX samples DEM data for normal route
tiles and distant mountain tiles. This is the most accurate way to apply a bias,
because the terrain is built directly from the source DEM at the adjusted
positions.

The Commit button is a Post Processing tool for quick offset testing using
existing terrain data only. Commit does not contact USGS and does not rebuild
terrain from DEM. It rewrites selected existing _y.raw height grids. If Create
Route Tiles is selected, normal terrain is shifted. If Create DM Tiles is
selected, existing TSRE-style DM tiles are shifted.

Post Processing is useful for finding the best offset after you notice a map or
marker alignment issue. However, it resamples the existing fixed terrain grid.
Normal route terrain is an 8m grid, so offsets that are not exact 8m multiples
must be interpolated. This can slightly soften or distort sharp features, and
repeated Post Processing shifts can compound that loss.

Recommended workflow:
  1. Build terrain with Advanced Geo Bias at 0.
  2. If alignment looks off, use Commit / Post Processing to test offsets.
  3. Once the best offset is known, rerun Run with that same Advanced Geo Bias
     value to rebuild from source DEM for the most accurate mesh possible.

Commit uses neighboring existing route tiles when the shift crosses a tile edge,
then merges shared edges before writing. Back up your route before using Commit.

11. TSRE alternate projection support
-------------------------------------
Some TSRE routes include a TsreGeoProjection statement in the route .trk file.
This is a TSRE route-centered projection used to reduce local map skew, often
for routes where street grids or other urban features need to line up more
squarely with map overlays.

During Scan and Run, SCO LIDEX checks the .trk file for TsreGeoProjection.

If TsreGeoProjection is not found:
  SCO LIDEX uses the standard MSTS / Open Rails interrupted Goode homolosine
  world-tile projection with the built-in 16m east and 16m south TSRE map
  compatibility correction.

If TsreGeoProjection is found:
  SCO LIDEX logs "Alternate projection detection: TsreGeoProjection found" and
  uses the TSRE route-centered projection for DEM sampling, route tile bounding
  boxes, distant mountain sampling, Marker selection, and KML selection. The
  standard-projection 16m correction is not applied.

The log also records the projection center and calculated meters-per-degree
values so testers can confirm which projection path was used.

This setting comes from TSRE and is route-specific. SCO LIDEX does not create
or edit the TsreGeoProjection statement; it only reads and honors it when
present.

12. Logs and retry files
------------------------
SCO LIDEX writes SCOLIDEX.log on the user's Desktop.
The log records the selected GUI settings at the start of each Scan, Run, or
Post Process operation and records elapsed time at the end of write operations.
Run logs also include separate human-readable USGS and Copernicus data-read
totals. These are practical estimates based on service responses plus the DEM
raster windows SCO LIDEX asks GDAL to read.

The message panel between Exit and Contact reports the active production stage:
- SCAN COMPLETE
- TILES - US - HIGH RES
- TILES - GLOBAL - LOW RES
- DM - PROCESSING
- OSM - DOWNLOAD
- OSM - PROCESSING
- OSM - MAKING MAPS
- OPERATION COMPLETE

Every message remains animated with cycling bullets while Scan or Run is still
processing. Intermediate completion messages such as TILES - COMPLETE,
DM - COMPLETE, and OSM / MAPS - COMPLETE remain animated because
later work or final cleanup is still active. Only the overall SCAN COMPLETE or
OPERATION COMPLETE outcome, failures, errors, aborts, and READY remain fixed.

Interface sounds follow the same production states:
- SCOpress plays for application button presses.
- SCOtic plays for checkbox and radio-button selections.
- SCOprogress plays for ordinary message-panel stage changes.
- SCOsuccess plays when Scan or Run completes successfully.
- SCObuzz plays for failure, error, or abort indications.

Sound playback is centralized so events do not overlap or produce dual sounds.
Missing or unavailable sound files never interrupt route processing.

While Distant Mountains are processing, the panel remains TILES - DISTANT
MOUNTAINS. DM source-resolution changes continue to update the counters and log
without replacing the stage message.

Stages are gated. If normal terrain has any failed tiles, SCO LIDEX finishes the
terrain batch, prints the retry list, and stops before DM or maps. Fix the error
or use Append before continuing. If DM has failures, SCO LIDEX finishes the DM
batch and stops before maps. OSM or map failures stop that stage. A failure or
abort message remains in the panel instead of being replaced by OPERATION
COMPLETE.

If the GUI fails before opening, SCO LIDEX writes a separate
SCOLIDEX-startup-error.txt file on the user's Desktop.

If normal terrain tiles fail during Run, SCO LIDEX marks retryable failed tiles
so Append can try them again later. This is usually the easiest recovery path,
especially for temporary USGS service or internet failures.

For most retryable failures:
  1. Wait a while if the log suggests USGS/service trouble.
  2. Select Append.
  3. Use the same route and selection options.
  4. Run again.

The log also prints a paste-ready block for targeted retries:

Failed tiles for SCOLIDEXTiles.txt:
# Paste the tile names below into ROUTE\SCOLIDEXTiles.txt and run Use Text File + Append.
-04bea740
-04bea744

Copy those tile names into ROUTE\SCOLIDEXTiles.txt only if you want to retry a
small specific set of tiles instead of running Append over the full selection.
Then select Use Text File, select Append, and run again.

Legacy SCOtopoTiles.txt files are still accepted, but new logs and examples use
SCOLIDEXTiles.txt.

If the log prints an "Unmappable failed tiles" block, those tile names are not
paste-ready retries. SCO LIDEX could not match them to ORTS world tile
coordinates.

13. Reporting tester issues
---------------------------
When reporting a problem, include:
- SCO LIDEX version number shown in the GUI.
- The route name.
- The options selected.
- SCOLIDEX.log.
- A screenshot if the issue is visual.
