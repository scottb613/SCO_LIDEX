# SCO LIDEX v1.200 Development Plan

## Purpose

Version 1.200 will extend SCO LIDEX in three independent areas while preserving the existing v1.100 terrain workflow as the safe default:

1. Add key-free, low-resolution global elevation coverage using Copernicus DEM GLO-30.
2. Create and apply 4096 x 4096 OpenStreetMap terrain textures that are visible when a route is opened in TSRE.
3. Add an experimental 4 m terrain output format for joint testing with the Open Rails development team.

This document is the implementation contract for v1.200. It describes the agreed behavior and safeguards; it does not itself change application behavior.

## Guiding Requirements

- The existing 8 m terrain workflow remains the default and must not regress.
- All new network sources must work without user accounts or API keys.
- Elevation source, map creation, and terrain output resolution remain separate user choices.
- Existing route selection methods remain authoritative: Route Tiles, Text File, Marker File, KML File, Track Database, and Tile Radius.
- Normal terrain and Distant Mountain terrain remain separately controlled.
- Every fallback, experimental mode, download source, skipped item, and failure must be visible in the running and saved logs.
- Append and Overwrite behavior must be defined independently for terrain, map data, and existing map-textured tiles.
- Route builders must be warned to back up a route before any operation that replaces terrain or material assignments.

## Proposed GUI Organization

The Options area will be reorganized into three clearly separated blocks.

```text
Elevation Data
  1 m
  5 m~
  10 m
  30m (global) - Low Resolution

Map Data
  [ ] Create Map Tiles
      OpenStreetMap via Geofabrik
      4096 x 4096 per terrain tile

Terrain Output
  (o) Normal - 8 m
  ( ) Experimental - 4 m
```

The current source statistics area will gain a `30m (global)` row. The GUI will display a noticeable `GLOBAL - LOW RES MODE` indicator whenever the 30 m global source is selected or used. Selecting 4 m output will display an equally noticeable `EXPERIMENTAL OUTPUT` indicator.

The Scan summary and final Run confirmation will state:

- Geographic selection and normal-tile count.
- Distant Mountain selection and count.
- Requested elevation source behavior.
- Whether global low-resolution data may be used.
- Whether map textures will be created and applied.
- Normal 8 m or experimental 4 m output.
- Existing files that will be skipped, replaced, or changed.
- Estimated Geofabrik download region and size when map creation is enabled.

## Task 1: Global 30 m Elevation Data

### Source

Use Copernicus DEM GLO-30 Public Cloud Optimized GeoTIFFs from the public AWS Open Data bucket:

```text
https://copernicus-dem-30m.s3.amazonaws.com/
```

Access is anonymous HTTPS. No AWS account, API key, or embedded credential is required.

### Source Priority

The existing US high-resolution sequence remains unchanged:

1. USGS 1 m
2. USGS Original Product Resolution, displayed as `5m~`
3. USGS/NED 1/3 arc-second, displayed as `10m`
4. Copernicus DEM GLO-30, displayed as `30m (global) - Low Resolution`

Copernicus GLO-30 is the global fallback when the existing US sources have no usable coverage. It must never be reported as high-resolution terrain merely because it is resampled onto an 8 m or 4 m output grid.

### Processing

- Resolve the required one-degree Copernicus COG names from each selected tile's geographic bounds.
- Read only the required raster windows through GDAL `/vsicurl/`.
- Feed samples into the existing projection, merge, NoData, retry, elevation-encoding, and rolling-tile pipeline.
- Preserve floating-point elevations until final terrain encoding.
- Apply the existing standard-route geographic correction consistently.
- Continue to use the separate `TsreGeoProjection` path where declared by the route.
- Treat missing COG objects as unavailable coverage, not zero elevation.
- Distinguish ocean-only areas from missing or failed data.
- Do not introduce a silent 90 m fallback. Any future GLO-90 support must be separately selected, labeled, counted, and documented.

### Identification and Logging

Every use must be reported explicitly:

```text
30m (global) - Low Resolution
Source: Copernicus DEM GLO-30 Public
Access: AWS Open Data
Data type: DSM
```

The documentation must explain that GLO-30 is a digital surface model and may include vegetation and structures. Normal and Distant Mountain statistics must count 30 m processing separately.

### Attribution

Add the required Copernicus attribution and licensing notice to the source documentation, distributed documentation, Help content, and third-party notices.

## Task 2: Create and Apply TSRE Map Tiles

### User-Facing Behavior

Add this independent option under Map Data:

```text
[ ] Create Map Tiles
```

When enabled, map processing uses the same normal terrain-tile selection already produced by Scan. Map textures are not generated for Distant Mountain tiles.

Each selected 2,048 m terrain tile receives one geographically aligned 4096 x 4096 rendered map image. The image is converted to an ACE texture and applied to the terrain file so it is visible immediately when the route is opened in TSRE.

### Data Source

Use raw OpenStreetMap vector data supplied through Geofabrik regional `.osm.pbf` extracts.

Discovery index:

```text
https://download.geofabrik.de/index-v1.json
```

The GeoJSON index provides stable region identifiers, coverage polygons, parent relationships, and current download URLs. LIDEX will choose the smallest practical extract or combination of extracts covering the selected route area.

Geofabrik is the primary source because its regional extracts are designed for bulk OSM distribution, require no key, contain complete unfiltered OSM data, and are updated daily. A public Overpass service may be retained only as an optional small-area or recovery fallback; it is not the primary route-scale source.

### Download and Cache Rules

- Show the proposed Geofabrik region name, file size, and data date during Scan.
- Require confirmation before a large regional download begins.
- Prefer state or subregional extracts over whole-country or continent downloads.
- Store extracts in a persistent SCO LIDEX map-data cache outside the route.
- Reuse cached data on subsequent runs.
- Provide a later explicit `Refresh Map Data` action; do not redownload daily extracts automatically on every Run.
- Use resumable `.part` downloads and retain safe partial downloads after interruption.
- Verify the completed file against Geofabrik's published checksum.
- Record extract identity, timestamp, size, checksum, and source URL in the run log.
- Never interpret a failed or incomplete extract as an empty map.

### Local OSM Processing

- Open the PBF using a local OSM/PBF-capable reader.
- Spatially filter features to the selected route bounds.
- Preserve the nodes, ways, tags, and referenced geometry required by the TSRE-style renderer.
- Cache an indexed local working subset when that materially improves repeated rendering.
- Render roads, railways, waterways, land areas, buildings, and other supported TSRE OSM feature classes with deterministic styling.
- Clip every feature precisely at the terrain-tile image boundary while retaining enough overlap during drawing to prevent clipped line strokes.
- Use one shared geographic conversion path for DEM placement, route selection, and map rendering.

### TSRE-Compatible Output

TSRE's current map workflow establishes the required output behavior:

- Render at 4096 x 4096 pixels.
- Name the applied ACE texture `<terrain-tile-base>_map.ace`.
- Place the ACE texture in the route's `TERRTEX` directory.
- Add or update the corresponding material/shader/texture record in the terrain `.t` file.
- Assign the map material across the terrain tile's 16 x 16 patches.
- Write the same per-patch UV layout used by TSRE so the single image spans the complete 2,048 m tile in the correct orientation.
- Preserve the height grid, water levels, terrain flags, patch centers, and unrelated terrain metadata.
- Save an intermediate 4096 x 4096 PNG only when useful for caching, diagnostics, or TSRE map-overlay compatibility; the applied ACE and `.t` assignments are what make the map visible on route open.

The TSRE source remains the behavioral reference for ACE conversion, texture naming, material creation, and patch UV assignments. LIDEX must reproduce the resulting files rather than requiring the user to load and apply each map manually in TSRE.

### Existing Terrain-Texture Safeguards

Applying a map texture changes terrain material assignments across all 256 patches in the tile. This can replace hand-painted terrain textures even though it does not replace terrain elevations.

Required safeguards:

- Scan detects existing map ACE files and existing map-material assignments.
- Scan warns when selected tiles already contain authored or non-map terrain painting.
- Append skips a valid, already-applied map texture.
- Append may create a missing map texture only when it can do so without silently replacing authored texture work.
- Overwrite explicitly replaces the existing applied map texture and assignments.
- A pre-change backup or recoverable copy of each modified `.t` file is required.
- Failures during ACE creation or `.t` modification must leave the original terrain file intact.
- File replacement must be transactional: prepare and validate the new outputs before replacing the originals.

### Attribution and Logs

Documentation and logs must identify:

```text
Map data: OpenStreetMap contributors
Distribution source: Geofabrik GmbH
License: Open Database License 1.0
```

The 4096 x 4096 rendered map is a produced work based on OSM data and must retain visible or accompanying attribution appropriate to its use.

## Task 3: Experimental 4 m Terrain Output

> Current status (2026-08-09): the isolated 512-grid writer, 4m metadata patch,
> complete KML-footprint generation, seam merging, all-or-nothing preparation,
> no-DM rule, and optional-map handoff are implemented. Export is deactivated
> behind `Program.Experimental4mExportEnabled = false`; the GUI remains fixed to
> Normal 8m until joint Open Rails testing resumes.

### GUI Selection

Add a dedicated Terrain Output block:

```text
(o) Normal - 8 m
( ) Experimental - 4 m
```

Normal 8 m remains selected by default. Experimental 4 m must be selected explicitly and must never be silently remembered as the safe default for a new session.

### Output Contract

Normal output remains:

```text
Physical tile size:     2,048 m
Height samples:         256 x 256
Post spacing:           8 m
terrain_nsamples:       256
terrain_sample_size:    8
Patch layout:           16 x 16
Cells per patch:        16 x 16
```

Experimental output becomes:

```text
Physical tile size:     2,048 m
Height samples:         512 x 512
Post spacing:           4 m
terrain_nsamples:       512
terrain_sample_size:    4
Patch layout:           16 x 16
Cells per patch:        32 x 32
_y.raw size:            524,288 bytes
```

The Open Rails development team will generalize its terrain mesh handling to consume the declared sample count and spacing instead of assuming 16 cells per patch. LIDEX will produce the experimental files and a repeatable test package.

### Encoding and Companion Files

- Preserve floating-point source elevations until the final floor/scale encoding step.
- Encode the 512 x 512 `_y.raw` grid consistently with terrain floor and scale metadata.
- Determine and document the required dimensions and behavior for `_f.raw`, `_n.raw`, and `_e.raw` companion files before publishing experimental output.
- Do not silently copy a 256-grid companion file into a 512-grid terrain tile unless Open Rails explicitly defines that behavior as valid.
- Preserve the standard 16 x 16 patch organization unless the joint ORTS test establishes a format change.
- Keep Distant Mountain terrain at its existing format. The 4 m option applies only to normal route terrain.

### Compatibility and Mixed Resolution

- Scan identifies every existing normal tile as 8 m, 4 m, invalid, or unknown.
- Append accepts an existing tile only when its resolution matches the requested output.
- Overwrite may convert selected terrain tiles between 8 m and 4 m after explicit confirmation.
- Mixed 8 m/4 m boundaries are experimental and require Open Rails seam validation.
- TSRE compatibility must be tested before describing 4 m output as editable in TSRE.
- Logs must state `EXPERIMENTAL 4m OUTPUT` for every affected tile and in the final summary.

### Joint ORTS Test Package

Generate matching 8 m and 4 m versions of a small 3 x 3 or 5 x 5 tile test area containing, where possible:

- Track and trackside objects.
- Steep terrain and shallow grades.
- Water or shoreline terrain.
- Normal tile seams.
- At least one 8 m/4 m mixed-resolution boundary.
- Fractional elevations.
- Map-textured and untextured comparison tiles.

Provide a validation manifest listing tile names, sample counts, sample spacing, raw-file sizes, floor, scale, minimum/maximum elevation, boundary differences, and checksums.

The ORTS test should compare:

- Successful loading and diagnostics.
- Visible terrain geometry.
- Ground-height queries and object placement.
- Tile seams and mixed-resolution stitching.
- Memory use, load time, frame rate, and view-distance behavior.
- Water and companion-file behavior.
- Agreement between rendering and physics interpolation.

## Shared Scan, Append, and Overwrite Rules

Scan remains mandatory unless Scan Override is explicitly selected.

### Append

- Terrain: skip only a valid existing tile matching the requested 8 m or 4 m format.
- Map data: skip only a valid ACE that is already referenced correctly by the terrain `.t` file.
- Global DEM: retry missing or failed terrain without disturbing valid completed tiles.
- Cached Geofabrik data: reuse it unless the user explicitly requests refresh.

### Overwrite

- Rebuild selected normal terrain in the chosen output format.
- Rebuild and reapply selected map textures when map creation is enabled.
- Preserve recoverable backups of every existing `.t` file changed by map application.
- Do not overwrite Distant Mountain data merely because normal terrain output resolution changed.

### Failure Isolation

Elevation and map processing must report independent outcomes. A map-source failure must not invalidate successfully generated terrain, and a terrain-source failure must not create or apply a misleading map texture to a missing terrain tile.

## Logging and Status Requirements

The live log and saved log must include:

- Application version and run mode.
- Route and selection source.
- Normal/DM tile counts.
- Requested terrain output format.
- Actual DEM source used per tile.
- Explicit `30m (global) - Low Resolution` reporting.
- Geofabrik region, URL, data timestamp, cache state, and checksum.
- Map render, ACE conversion, and `.t` application result per tile.
- Existing texture warnings and backup locations.
- 8 m/4 m format detection and conversion decisions.
- Retry, skip, and failure reasons.
- Final counts for 1 m, 5m~, 10 m, 30 m, map-created, map-applied, skipped, and failed items.

## Implementation Order

1. Establish shared v1.200 option/state models and redesign the GUI blocks without changing terrain behavior.
2. Add source/status/log support for the 30 m category.
3. Implement and validate Copernicus GLO-30 discovery and window sampling.
4. Add Geofabrik index discovery, region selection, size reporting, download, checksum, cache, and resume behavior.
5. Add local PBF filtering and the TSRE-compatible 4096 x 4096 vector renderer.
6. Implement ACE creation and transactional terrain `.t` material/UV application using TSRE as the reference.
7. Add normal/experimental terrain output selection and 512 x 512 height-grid writing.
8. Resolve companion raw-file behavior with the ORTS developers and produce the conformance test package.
9. Run regression, route-safety, TSRE-display, network interruption, and ORTS experimental tests.
10. Update Help, README, changelog, third-party notices, distributed documentation, and release highlights.
11. Build the distribution, verify its contents and executable metadata, save the release snapshot, tag the finalized source, and publish only after test acceptance.

At minimum, validate these combinations:

| US high resolution | On | Normal 8 m | Standard terrain plus applied 4096 map textures |

## Release Acceptance Criteria

Version 1.200 is ready for release only when:

- Normal 8 m output remains regression-compatible with v1.100.
- Copernicus GLO-30 works without credentials and is always labeled low resolution.
- Missing global data never becomes false zero-elevation terrain.
- Geofabrik data can be discovered, downloaded, verified, cached, resumed, and reused.
- Every generated map is 4096 x 4096 and geographically aligned with its terrain tile.
- Applied map ACE textures display automatically when the route is opened in TSRE.
- Existing hand-painted terrain cannot be overwritten without an explicit warning and recoverable backup.
- Experimental 4 m output matches the agreed metadata and file-size contract.
- ORTS successfully loads and renders the experimental test package.
- Mixed-resolution and companion-file behavior is documented from actual testing.
- Help, source documentation, distribution documentation, attribution, version metadata, ZIP contents, source snapshot, Git tag, and release page all agree.

## Deferred Work

The following ideas are valuable but are not part of the three-feature v1.200 commitment unless separately approved:

- TDB-guided railway formation smoothing and cut/fill blending.
- Bridge, tunnel, yard, and manual terrain exclusion masks.
- Automatic TDB-to-OSM alignment scoring.
- Global 90 m fallback.
- Automatic Geofabrik replication-diff updates.
- A new compressed ORTS-native terrain format.
- Additional 4 m Distant Mountain formats.
