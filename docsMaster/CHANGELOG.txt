SCO LIDEX Changelog
===================

v1.401 HOTFIX
-------------
- Preserved fractional-metre DEM elevations from source sampling through
  fallback mosaics, neighbor fill, rolling seam/corner merging, terrain patch
  averages, and external `_y.raw` encoding. v1.400 rounded generated elevation
  samples to whole metres, which produced visible terracing—especially in 4m
  terrain. Both 8m and 4m output now retain the available source precision.
- Changed terrain encoding to use a floored sample base and a minimum 1/256m
  scale, while expanding the selected scale only when a tile's elevation range
  requires it. Existing decoded short-grid post-processing remains compatible.
- Added a rolling-terrain regression check that proves fractional 4m elevations
  survive raw encoding and continues to verify bounded memory, shared edges,
  shared corners, file sizes, map-material repair, and GUI progress messages.
- Tree-row map lines and plantable PolyVeg strips now use the exact
  natural=wood woodland color. Existing cached derivatives are invalidated so
  reparsing cached route OSM data applies the corrected color.
- Reworked the Scan, Run, terrain, DEM, Distant Mountain, and final-summary logs
  around readable uppercase sections, result-first detail lines, deliberate
  spacing between DEM products, and indentation that preserves full diagnostic
  detail without timestamping every fast operation. Internal STATUS control
  tokens remain available to GUI counters without appearing in the human log;
  Abort now finishes the active unit safely and ends with a clean summary.
- Standardized ownership and licensing headers across every tracked source and
  helper script, and added matching author, product description, copyright, and
  GPL metadata to the compiled application.

v1.400
------
- Corrected DEM handling for the ETRY Kentucky data case. Raster band scale and
  offset plus metre, US survey-foot, and international-foot vertical units are
  normalized to metres before interpolation. Declared NoData, invalid finite
  sentinels, implausible elevations, and extreme four-cell discontinuities are
  rejected so the established lower-resolution fallback fills missing posts
  instead of encoding terrain spikes or walls. Added a focused regression probe.
- Redesigned the main window as a TSRE-inspired dark operator console with
  charcoal work surfaces, subtle grey card borders, amber section accents, a
  restrained text-only LIDEX masthead, and a dark Windows title bar.
- Consolidated Mode, Selection, and Build Options into a centered fixed sidebar.
  Build Options now pair Route Tiles with HD Mesh Tiles and OSM / Map Tiles
  with HD Map Tiles; DM Tiles remains the middle item in the left column.
  Removed the disabled Mosaic Tiles placeholder and the unstable Text Size
  feature.
- Route selection, live status, Advanced Geo Bias, commands, and the framed
  Running Log share one workspace. The 1024x700 minimum layout requires no
  sidebar scrollbars; only the Running Log retains its vertical scrollbar.
  Normal resizing remains available, maximizing is disabled, and startup bounds
  stay inside the active monitor work area.
- Refined the dark interface with an unclipped masthead, readable disabled
  choices, dark custom sliders and numeric spinners, and matching dark cache-exit
  and confirmation dialogs. Exit choices now distinguish the preferred Keep All
  action from viable Purge and Cancel choices, the cache header fills cleanly, and
  Running Log text uses a softer contrast. Enabled actions use a thin amber
  outline; only the next workflow step is strong (Scan initially, then Run after
  a passing scan). Post-scan focus follows Run, while active-operation focus
  stays in the Running Log so Contact never receives default-button emphasis.
  Tile Radius defaults to 2, the centered version label is slightly larger, and
  Help and Contact use matching dark window treatment.

v1.300
------
- Added Options controls for HD terrain meshes and HD map images. Route, DM,
  and OSM/map creation default on. Terrain remains locked to Normal - 8m until
  Enable HD Mesh Tiles is selected; maps default to 2048x2048 and Enable HD
  Map Tiles selects 4096x4096 output.
- Scan skips route terrain resolution inspection when Create Route Tiles is
  off. When route terrain is selected, Scan remains read-only: it flags mixed
  8m/4m output and records approval, while Run performs the conversion.
- Added short, behavior-specific tooltips for every control in Options.
- Added `natural=tree_row` processing for rural terrain. Each OSM way becomes
  a separate 10 m-wide dark-green woodland PolyVeg feature at drawOrder 30,
  above ordinary woodland and agriculture. Existing permanent exclusions still
  carve the derived strip, and woodland-category planting includes tree rows.
- Distinguished confirmed DEM no-coverage results from temporary USGS source
  hiccups. A hiccup now tries cached products first; if cached data cannot
  complete the requested source tier, the tile is not generated from a lower
  resolution, is marked for Append retry, and appears in the failed-tile list.
  HD Test - 4m failures now print the same targeted retry block as 8m terrain.
- Enabled both terrain outputs with the final labels Normal - 8m Tiles and
  HD Test - 4m Tiles. Scan now checks the resolution of every terrain tile on
  the route, independent of the selected coverage mode. After styled user
  approval, Run forces every mismatched tile into the selected output and
  rebuilds it from current elevation data, even when it was outside the
  original selection; matching tiles remain available for normal mode handling.
- Promoted the 4m generator to the bounded rolling-row architecture used by
  production 8m terrain. Completed grids now enter the virtual seam mesh and
  update GUI counters immediately; completed rows are edge/corner merged,
  written, and released instead of retaining the full route. Distant Mountain
  generation now follows the same bounded rule. Added synthetic multi-row
  seam, output-size, memory-window, and live-counter verification.
- Made route summaries and Advanced Geo Bias post-processing resolution-aware,
  including 512x512 reading, resampling, seam merging, and writing for 4m.
- Terrain generation now detects obsolete `_map.ace` materials embedded in
  normal `.t` tiles and restores the default `terrain.ace` material and UV
  state. Terrain coordinates, height/patch data, water flags, world files, and
  the separate `terrain_maps` PNG overlay remain intact.
- Renamed the tracked and distributed documentation directory from `docs` to
  `docsMaster`. Packaging, in-application Help discovery, public links, build
  notes, synchronized document rules, and the PolyVeg contract path now use
  the new canonical location.
- Added a persistent, spatially indexed route OSM working cut. The regional
  PBF is streamed once, complete geometry is clipped to the buffered union of
  route terrain tiles, and map/PolyVeg work reuses the compact route source
  until either the PBF stamp or terrain footprint changes.
- Replaced the progressively growing route-wide visible-surface overlay with
  bounded terrain-section stacking. Each section includes a one-foot overlap
  halo, preserves global draw/source order, and recombines all retained pieces
  under their original stable source identity before validation and export.
- Prevented final feature assembly from re-snapping already cleared section
  geometry across permanent exclusions. Exclusion and overlap tolerances are
  now verified inside each bounded section, avoiding another route-wide overlay
  during final validation.
- PolyVeg route coverage now follows every normal terrain .t tile rather than
  only object-bearing .w files. Bare visible terrain is exported and plantable;
  the complete terrain footprint also invalidates incomplete working caches.
- Renamed Create Map Tiles to Create OSM/Map Tiles, removed the unused 10m
  counter from the Distant Mountains status column, and repaired invalid
  exclusion geometry after clipping/buffering before the PolyVeg union.
- Added a readable, indented OSM/PolyVeg processing section with timestamped
  stage starts and completions. Long stages print a concise five-minute
  heartbeat without repeated elapsed-duration text. Counted work now reports
  ten evenly spaced checkpoints: source-read percentage plus feature count,
  and completed/total counts for PolyVeg work, exclusions, and GeoPackage output.
- Added a one-foot terrain-vegetation clearance and common 0.10 m overlay
  precision to prevent non-noded OSM boundary intersections during final
  PolyVeg exclusion and visible-layer subtraction.
- Preserved inner rings while rendering filled OSM map polygons, so river and
  lake islands remain unpainted instead of being flattened into filled water.
- Reduced PBF classification overhead by consuming point records for relation
  integrity without wrapping, validating, styling, or exporting unused point
  geometry. Route rejection now precedes expensive topology repair.
- Restored the faster route-wide PolyVeg stacking algorithm after testing showed
  that rebuilding local candidate unions became progressively slower on dense routes.
- Retained the simple worldwide Geofabrik model: select the smallest single
  official regional extract covering the route, then build map tiles and the
  validated PolyVeg contract directly from that source.
- Replaced the remaining native Windows message boxes with SCO LIDEX-styled
  information, warning, error, and confirmation dialogs. Popup colors,
  typography, spacing, buttons, sounds, and owner-centered behavior now match
  the main application and its existing Help, Contact, and cache windows.
- Replaced forest-polygons.geojson with schemaVersion 2
  osm_data\polyveg-polygons.geojson. Twelve canonical rural categories are
  exported as final mutually exclusive surfaces using the shared F3/LIDEX RGB
  palette, exact OSM key=value style IDs, map draw order, and stable identity.
- Carves permanent building, developed/urban, road, railway, trail, open-water,
  waterway-clearance, and bare-ground exclusions from every category. Wetland
  and agriculture remain plantable categories rather than self-exclusions.
- Validates required properties, EPSG:4326, polygon-only non-empty geometry,
  category overlap, permanent-exclusion intersections, and manifest counts
  before atomically promoting the GeoPackage, manifest, polygons, and
  exclusions. The obsolete forest output is removed after successful handoff.

v1.200
------
- Refined the standard-projection calibration from 16m east / 16m south to the
  calculated 11m east / 16m south baseline. Advanced Geo Bias remains an
  additional route-specific adjustment.
- Changed Distant Mountains to Copernicus GLO-30 exclusively. The 30m source is
  resampled onto the existing 128m low-terrain grid; DM-only Scan and Run no
  longer query USGS 1m, 5m~, or 10m.
- Added route-cache-first OSM discovery. LIDEX checks the selected route first,
  then sibling and registered route caches, and uses a covering PBF directly
  from its existing location without copying it.
- Added route-local OSM derivative output during Create Map Tiles:
  osm_data\route-geodata.gpkg, osm_data\route-geodata.json, and the TSRE
  compatibility file osm_data\forest-polygons.geojson.
- Added indexed WGS84 GeoPackage layers for woodland, scrub, heath, grassland,
  wetland, water, waterways, buildings, developed land, agriculture, roads,
  railways, and bare ground. Habitat geometry uses exact world-tile coverage;
  transport, water, building, and developed context retain a 2048m margin.
- Added PBF and world-tile fingerprint freshness checks. Fresh downloads force
  derivative regeneration; unchanged current packages are reused. A PBF reused
  from another route remains in place while derivatives are saved to the active
  route.
- Added validation and atomic three-file promotion for route derivatives.
  Invalid source geometry is repaired when possible and repair/skip totals are
  recorded in route-geodata.json.
- Removed large AppData PBF/partial-download storage and migration. A fresh PBF
  is downloaded into the selected route only when no covering route cache
  exists; purging the cached PBF is the explicit refresh operation.
- Added the full Beast of Burden SCO LIDEX header graphic and restrained title
  plate, increased the default window height without shrinking the log, and
  added a disabled Create Mosaic Tiles teaser.
- Locked the packaged GUI to Normal - 8 m and renamed the disabled evaluation
  teaser to Testing - 4 m. The internal selected-footprint 4m path remains
  available for coordinated testing and can sequence optional DM/maps.
- Changed Scan from all-or-nothing service gating to a per-source capability
  plan covering USGS 1m, 5m~, 10m, Copernicus 30m global, and Geofabrik maps.
- Added a final source-status and Run-plan summary. Individual outages remain
  clearly marked FAILED, while a usable fallback produces PASSED WITH WARNINGS
  and enables Run for the viable selected stages.
- Source results use separate Data, Source, and PASSED/FAILED lines for easier
  reading in both Scan and Run logs.
- Added explicit USGS detail in Scan and Run so SERVICE ONLINE / NO ROUTE
  COVERAGE cannot be mistaken for a service outage.
- A malformed USGS product response no longer prevents Copernicus fallback.
- Corrected GUI status parsing so Data Source `Status: FAILED` lines remain
  informational and cannot suppress the final operation-complete state.
- Added explicit terrain, Distant Mountain, and OSM/map completion statuses.
- Moved downloaded Geofabrik PBF extracts into each route's
  osm_data\geofabrik folder and added a portable osm-cache.json manifest.
- Added direct reuse of covering PBFs from other known route caches without
  duplicating large downloads.
- Added an AppData cache-registry-v1.json index for discovering route-local
  caches while keeping the route manifest authoritative.
- Replaced whole-cache exit deletion with unchecked per-cache selections for
  regional extracts and incomplete downloads. The small shared Geofabrik index
  and route derivative files remain in place and are never offered for deletion.
- Purge Selected with no checked cache now plays the failure buzz, deletes
  nothing, and keeps the exit dialog open.
- Classified generated terrain_maps PNG files as permanent route output; cache
  cleanup never lists, deletes, or removes those map images or their folder.
- Sources that fail or report no representative coverage during Scan are not
  polled during the following Run. Copernicus can carry global normal terrain
  and is the exclusive Distant Mountain source independently of USGS.
- A Geofabrik outage no longer blocks terrain or DM. Map generation uses a
  usable cached regional index/PBF without polling the failed service, or skips
  only the map stage when no valid cache exists.
- Added immediate SCANNING status and a one-second working indicator that cycles
  active statuses through zero, one, two, and three real bullets on each side.
  Intermediate terrain, Distant Mountain, and map completion stages remain
  animated while Run continues. Only overall Scan/Run completion, failure,
  error, abort, and ready states remain fixed.
- Shortened Distant Mountain message-panel stages to DM - PROCESSING,
  DM - COMPLETE, and FAILURE - DM so animated bullets fit the panel cleanly.
- Create Map Tiles writes directly to TSRE's F3
  `terrain_maps/<X*10000+Y>.png` overlay cache. Matching PNGs are overwritten;
  no map ACE is created and terrain `.t` materials/UVs remain unchanged.
- Corrected F3 cache naming for the route coordinate convention: TSRE map Y is
  the negative of terrain Z, so the filename hash is `X*10000-Z` in LIDEX.
- Added non-overlapping interface audio for button presses, checkbox/radio
  selections, ordinary status changes, successful Scan/Run completion, and
  failure/error/abort indications.
- Assigned SCOpluck to ordinary status messages and SCOsuccess to successful
  Scan and Run completion.
  All supplied WAV assets are retained in source and distribution output.
- Expanded the center message panel to report Scan, terrain-source, DM, OSM
  download/processing/rendering, completion, failure, and abort stages using one
  consistent color. Terrain and DM failures now finish their current batch and
  gate all later production stages so Append/correction can occur first.
- Added an isolated experimental 4m normal-terrain test path: selected tiles are
  generated as 512x512 grids, shared edges/corners are merged, and optional DM
  and map stages can run afterward. The established 8m writer is unchanged.
- Kept the packaged GUI fixed to Normal - 8 m while retaining the internal 4m
  evaluation path for coordinated Open Rails format testing.
- Restored the Route Path Browse button with the Windows folder-selection dialog.
- Added a clearly labeled Recent menu backed by
  %LocalAppData%\SCOLIDEX\route-history.json, retaining the five most recent valid route
  folders and automatically filtering missing or invalid entries.
- Kept the WinForms entry thread in STA mode so route autocomplete and the
  Windows folder-selection dialog initialize reliably.
- Uses a dedicated Recent button instead of a native ComboBox, improving
  contrast and avoiding re-entrant native drop-down behavior.
- Enabled Create Map Tiles with anonymous Geofabrik OpenStreetMap regional PBF
  extracts, resumable local caching, and read-only source/driver Scan checks.
- Added self-contained 4096x4096 TSRE ACE reference-texture writing without an
  external editor or MSTS tool.
- Uses the same corrected terrain projection for every OSM vertex and validates
  tile corners/center; the Austria acceptance route measured 0.000000 pixels.
- Added transactional temporary output and timestamped backups for replaced map
  ACE files.
- Loads selected-route PBF geometry once, retains it for the complete run, and
  renders two map textures concurrently without a geometry reload.
- Replaced the initial dark LIDEX map theme with a direct port of TSRE's OSM
  vector background, feature colors, road casings/widths, and drawing order.
- Corrected Geofabrik selection to require one extract that covers every
  selected terrain tile; multi-state routes now select the broader regional
  extract instead of the smallest extract containing only the route center.
- Treats genuinely featureless OSM tiles as valid TSRE background textures
  instead of aborting the map run.
- Matched TSRE's OSMFeatures layer priorities so water polygons render above
  overlapping residential, forest, and other land-use polygons.
- Preserves the complete OSM node stream while filtering finished geometry,
  allowing long river, lake, and forest multipolygon relations to remain
  complete when their remote vertices extend beyond the selected route area.
- Rebuilds TSRE's normal terrain database index whenever Marker, KML, Track
  Database, or text-list selection creates route tiles, ensuring newly created
  .t, _y.raw, and world-file sets appear as editable base terrain in TSRE.
- Added anonymous Copernicus DEM GLO-30 Public fallback coverage after the
  existing USGS 1m, 5m~, and 10m sources for normal terrain, and made it the
  exclusive Distant Mountain source.
- Added separate 30m (global) status counters, low-resolution mode indicator,
  source logging, scan validation, and data-read accounting.
- Increased the window height to accommodate the new status row without
  reducing the running-log area.
- Moved Copernicus tile discovery and COG reading into Program.Copernicus.cs.
- Separated selection, terrain, Distant Mountain, projection, Copernicus, and
  map generation into major partial-class components without changing the GUI.
- Moved map-cache size reporting to a unified exit dialog with Keep Cache,
  Purge Cache, and Cancel Exit choices for both the Exit button and window X.
