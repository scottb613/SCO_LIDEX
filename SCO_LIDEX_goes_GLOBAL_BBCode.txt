Hi Folks,

Well - a new update.

When I first posted about SCO LIDEX, one of the first questions was whether it could build terrain outside the United States. At the time, the honest answer was no. LIDEX depended on USGS elevation data, so our friends building routes in Europe, the UK, Australia, and most of the rest of the world were left standing at the station.

That answer has changed.

[b]SCO LIDEX v1.200 now provides worldwide terrain-building coverage.[/b]

It still uses the best available high-resolution USGS data for United States routes, but it can now fall back automatically to the public Copernicus GLO-30 global elevation dataset. The same release also builds Distant Mountains and can create detailed OpenStreetMap map tiles without making the user manually hunt down and install map images.

In plain English - point LIDEX at the route, select what you want, run Scan, and let the program sort out which data sources can do the job.

[b]============================================================[/b]
[b]HIGH-LEVEL FEATURES[/b]
[b]============================================================[/b]

[list]
[*][b]Worldwide terrain coverage[/b] using the key-free Copernicus DEM GLO-30 Public dataset.
[*][b]High-resolution U.S. terrain remains intact[/b] using the established USGS source sequence.
[*][b]Automatic source fallback[/b] uses the best available elevation source and fills unresolved terrain from the next viable source.
[*][b]Global Distant Mountains[/b] can be generated where USGS 10-meter coverage is not available.
[*][b]OpenStreetMap map tiles[/b] are created automatically from anonymous Geofabrik regional extracts.
[*][b]No manual map downloads[/b] and no separate map-image installation step.
[*][b]No API keys[/b] for Copernicus, Geofabrik, or USGS public data.
[*][b]Read-only Scan[/b] checks every selected data source before LIDEX writes route terrain.
[*][b]Clear source reporting[/b] shows PASSED or FAILED for each source and explains the difference between a service outage and simply having no coverage for the route.
[*][b]Independent production stages[/b] allow viable terrain, Distant Mountain, or map work to continue when another source is unavailable.
[*][b]Append and Overwrite modes[/b] remain available for new terrain and deliberate route rebuilds.
[*][b]Resumable OSM downloads[/b] continue an interrupted regional download instead of throwing away the work already completed.
[*][b]Selective cache cleanup[/b] lets the user choose individual OSM downloads to remove when exiting LIDEX.
[/list]

[b]============================================================[/b]
[b]THE ELEVATION SOURCES[/b]
[b]============================================================[/b]

LIDEX checks the elevation sources in this order:

[list=1]
[*][b]USGS 3DEP 1-meter DEM[/b] - the highest-resolution source used by LIDEX for covered United States routes.
[*][b]USGS Original Product Resolution - shown as 5m~[/b] - used where applicable when 1-meter coverage does not resolve every terrain post.
[*][b]USGS/NED 1/3 arc-second - shown as 10m[/b] - the established lower-resolution U.S. fallback and Distant Mountain source.
[*][b]Copernicus DEM GLO-30 Public - shown as 30m (global)[/b] - the key-free worldwide fallback supplied through AWS Open Data.
[/list]

Note: 30-meter global data is not magically the same thing as 1-meter LIDAR. Copernicus GLO-30 is a lower-resolution digital surface model, and its elevations may include vegetation, buildings, and other infrastructure. It gives route builders practical worldwide coverage - it does not pretend every country suddenly has USGS-quality 1-meter terrain.

LIDEX identifies global processing clearly in the interface and log. On a U.S. route, it will still try the finer USGS sources first and use Copernicus only where the selected route needs it.

[b]============================================================[/b]
[b]OPENSTREETMAP MAP TILES - NO MANUAL DOWNLOADS[/b]
[b]============================================================[/b]

Select [b]Create Map Tiles[/b] in SCO LIDEX and use the normal Scan and Run workflow. LIDEX finds the required Geofabrik regional OpenStreetMap extract, downloads it, and creates a 4096 x 4096 map image for each selected normal terrain tile.

There is no separate map website to visit, no pile of images to name, and no manual map installation.

After opening the route, use the [b]MAP TILE SHOW/HIDE[/b] button to display or hide the generated map tiles.

That's it.

[b]============================================================[/b]
[b]WHERE LIDEX STORES THE OSM DATA[/b]
[b]============================================================[/b]

This is new for v1.200.

The large regional OpenStreetMap extract is stored with the route:

[code]<Route>\osm_data\geofabrik\<region-id>.osm.pbf[/code]

LIDEX also writes the route's OSM cache description here:

[code]<Route>\osm_data\osm-cache.json[/code]

The small shared Geofabrik regional index and the route-cache registry remain under:

[code]%LocalAppData%\SCOLIDEX[/code]

In other words - the large PBF download stays in the route folder where it can be seen and managed, rather than quietly filling a hidden application-data folder. If the same route is processed again, LIDEX can use the existing valid download instead of fetching it all over again.

When exiting LIDEX, the cache screen lists regional PBF files and incomplete downloads individually. Every purge box is clear by default. The small shared index is not included in the purge, and LIDEX never deletes the generated map images from the route's [b]terrain_maps[/b] folder.

[b]============================================================[/b]
[b]BASIC WORKFLOW[/b]
[b]============================================================[/b]

[list=1]
[*][b]Back up the route.[/b] Terrain work is still terrain work, and a backup remains cheap insurance.
[*]Select the route folder in SCO LIDEX.
[*]Choose normal terrain, Distant Mountains, and/or Create Map Tiles.
[*]Run [b]Scan[/b] and review the status of every data source.
[*]Run the production stages that Scan has enabled.
[*]Open the route and use [b]MAP TILE SHOW/HIDE[/b] to view the generated map tiles.
[/list]

LIDEX can work from existing route tiles or build coverage from a tile list, marker file, KML file, or track database. Scan remains read-only. Run writes only the production stages you selected and that Scan determined had a viable data source.
