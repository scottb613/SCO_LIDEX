SCO LIDEX - Default Terrain Geometry Placement Correction
==========================================================

Observed problem
----------------
Terrain generated on several default-projection routes consistently needed
an east/south correction to line up with the TSRE/OpenStreetMap route overlay.
The coordinate comparison resolves that correction to approximately 11 meters
east and exactly 16 meters south.

The 16-meter north/south error is exactly two normal ORTS terrain-post
intervals. The east/west correction is not an exact 8-meter post multiple and
is most accurately applied while sampling the source DEM.

What was checked
----------------
The normal terrain grid itself is positioned correctly:

* The raw grid contains 256 by 256 stored posts.
* Post spacing is 8 meters.
* Post (0,0) is at the northwest tile corner: X=-1024, Z=+1024.
* Stored posts cover 255 intervals, or 2040 meters.
* The east and south boundary posts are supplied by neighboring tiles.

Therefore, the 2040 meter stored span inside a nominal 2048 meter tile is
intentional and was not the source of the placement error.

Root cause
----------
The older Open Rails WorldLatLon converter and TSRE's map-coordinate
converter use slightly different Interrupted Goode Homolosine image origins.

Older ORTS constants used by SCO LIDEX:

    Upper-left X = -20,013,965
    Upper-left Y =   8,674,008

TSRE map converter constants:

    Image left = -20,015,000
    Image top  =   8,673,000

After the different tile-index formulas are accounted for, the north/south
difference is exactly 16 meters. The calculated east/west difference is
approximately 11 meters. SCO LIDEX now keeps that calculated value instead of
rounding it to a complete 8-meter terrain-post interval.

Implemented correction
----------------------
For routes using the standard MSTS/Open Rails projection, SCO LIDEX now
applies a built-in terrain placement correction of:

    11 meters east
    16 meters south

The correction is applied at geographic sampling time. Every selected normal
terrain tile and Distant Mountain tile uses the same corrected geographic
frame, preserving seamless transitions.

Routes containing TsreGeoProjection are not given this standard-projection
correction. They continue to use their route-specific TSRE projection.

The Advanced Geo Bias controls remain available. Their values are additional
to the built-in standard correction and should normally remain at zero.
